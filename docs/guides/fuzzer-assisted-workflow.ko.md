# Fuzzer 설정 보조 기능 사용법

## 적용 전에

이 변경은 Sniper 소스에 포함되는 기능입니다. 누적 소스/패치 ZIP은 macOS 설치용 DMG나 완성된 `.app`이 아닙니다. 전달된 ZIP의 `README.ko.md`에 적힌 기준 소스와 적용 절차를 따르세요. 이미 누적 패치를 적용한 작업 폴더에 같은 패치를 다시 적용하지 마세요.

웹 화면은 실행 파일에 포함됩니다. 파일만 복사하거나 기존 앱을 다시 여는 것으로는 반영되지 않으며, 적용한 소스로 다시 빌드해야 합니다. 개발 실행은 저장소의 README/AGENTS 안내를 따르세요. macOS 앱 묶음은 저장소의 `packaging/macos/make-app.sh` 경로를 사용합니다. 기존 앱이나 세션을 덮어쓰기 전에 별도 위치에서 새 빌드를 확인하세요.

이 안내가 macOS 설치, 서명, 공증 또는 실제 Mac 화면 검증 완료를 뜻하지는 않습니다. 최종 ZIP의 검증 보고서에서 통과 항목과 미검증 항목을 확인하세요.

## 빠른 사용 순서

1. HTTP History에서 요청을 선택하고 `Send to Fuzzer`를 누릅니다. HTTP Replay에서도 보낼 수 있습니다. 다른 요청을 가져와도 준비한 payload 목록은 유지됩니다.
2. 요청의 값을 선택하고 `Mark selection`을 누릅니다. `Find query or form values`에서 현재 요청의 query/form 값을 골라 `Mark value`를 눌러도 됩니다. 같은 이름의 파라미터는 개별 항목으로 표시되며 인코딩은 그대로 유지됩니다. `Undo marker`는 그 뒤 요청을 수정하지 않았을 때 마지막 표시를 되돌립니다.
3. Payload를 한 줄씩 붙여 넣거나 UTF-8 텍스트 파일, 작은 경계값 preset, 정수 범위를 사용합니다. 기본은 기존 목록에 추가입니다. `Replace list`는 기존 목록을 바꿉니다.
4. 상단에서 실제 연결 대상, HTTP 버전, marker 수, `N payloads → N planned requests`를 확인합니다. 여러 marker가 있어도 각 요청에는 같은 payload가 모두 들어갑니다. 위치별 조합 실행은 하지 않습니다.
5. `Preview template-expanded requests`를 열어 최대 3개 샘플을 확인합니다. Content-Length는 본문 길이에 맞춰 재계산됩니다. 샘플은 템플릿 확장 미리보기이며 실행 시 Match/Replace 등으로 실제 전송 내용이 달라질 수 있습니다. 큰 샘플은 생략되거나 표시가 잘렸다는 안내가 나옵니다.
6. 본인 소유 또는 테스트 허가를 받은 대상인지 확인한 뒤 `Start`를 누릅니다. 현재 엔진은 순차 실행 후 결과를 반환합니다. 실행 중 취소나 실시간 진행률 기능은 없습니다.
7. 결과의 상태 코드 그룹, 본문 크기, 소요 시간으로 필터링하고 정렬합니다. 크기는 응답 본문 bytes입니다. 결과를 선택해 요청/응답을 확인하고, `Set compare base` 후 다른 결과의 `Compare selected`로 기존 비교 화면을 엽니다.

## 빈 값과 파일 의미

- 공백은 제거하지 않습니다. `$&`, `$1`, `$payload$` 같은 payload 문자열도 문자 그대로 사용합니다.
- 빈 줄은 빈 payload입니다. 마지막 줄바꿈 하나는 구분자로만 취급합니다. 빈 payload 하나만 넣으려면 빈 줄 하나를 입력합니다.
- 파일의 CRLF와 CR은 붙여 넣기와 동일하게 줄바꿈으로 처리됩니다. UTF-8 BOM은 문자로 유지합니다. 잘못된 UTF-8은 변환하지 않고 거절합니다.
- 파일을 읽는 동안 요청/목록/세션이 바뀌면 오래된 읽기 결과를 적용하지 않습니다.
- 완전한 UTF-8 본문에서만 본문 값 선택을 돕습니다. Base64/바이너리/잘린 본문을 일반 form 값처럼 바꾸지 않습니다. Base64 본문에 직접 marker를 넣는 일부 API 기능은 이 화면에서 지원하지 않습니다.

## 저장된 실행 다시 보기

`View or reuse a saved run`에서 `Refresh` 후 실행을 선택합니다.

- `View results`: 현재 요청과 payload, 연결 대상 설정을 그대로 두고 저장된 결과를 봅니다.
- `Reuse setup`: 확인 후 요청과 payload 초안을 교체합니다. 원래 원문 포맷, source transaction, 별도 target override는 저장된 실행에 없으므로 복구하지 않습니다. 현재 초안의 무관한 source/target도 제거합니다. 저장된 template HTTP 버전이 있으면 유지하고, 없으면 HTTP/1.1 초안이 됩니다. 실행 전에 대상과 버전을 다시 확인하세요.
- 줄바꿈이 들어 있는 API payload나 편집기 한도를 초과한 실행은 초안으로 복원하지 않습니다. `View results`로 보는 것은 가능합니다.

## 한도

- Payload 최대 5,000개, 각 64 KiB, payload 바이트 합계 4 MiB
- Payload 편집기 텍스트와 가져올 파일도 각각 4 MiB 이하. 편집기 한도는 줄 구분자까지 포함하므로 바이트 합계 한도와 다릅니다.
- 요청 편집기 텍스트 2 MiB, marker 최대 128개, payload별 확장 요청 예산 4 MiB
- 서버는 전송 전에 모든 확장 요청을 검증합니다. 계획 요청 수는 전송 성공 수가 아닙니다.
